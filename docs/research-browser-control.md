# Исследование: идеи из Browser Control для better-axi

Дата: 2026-10-19. Источник — публичный репозиторий [anomalyco/browser-control](https://github.com/anomalyco/browser-control), просмотренный 2026-10-19. Ниже рассматриваются идеи продукта и процесса, а не совместимость компонентов.

## Краткий вывод

Browser Control — локальный драйвер Playwright для существующего Chromium через расширение и relay. Он оставляет планирование вызывающему агенту. Это близко к границе ответственности better-axi: браузерные действия остаются в проекте, а структурированные решения передаются PAG. Переносить стоит отдельные рабочие принципы, не весь стек Playwright/расширения.

## Идеи по приоритету

1. **Проверять результат каждого действия.** Browser Control требует перечитать страницу после действия или ручной передачи управления; успешный клик или подтверждение человеком не доказывает, что цель достигнута ([README: handoff](https://github.com/anomalyco/browser-control/blob/main/README.md#pause-for-human-only-steps)). В better-axi цикл уже перечитывает страницу на следующем шаге, но контракт `nav` может явно считать результат проверенным только после свежего snapshot и наблюдаемого постусловия ([`loop.mjs`](../core/agent/loop.mjs)). Это самый дешёвый и полезный перенос.

2. **Добавить синтетические проверки устойчивости `nav`.** Gauntlet Browser Control запускает локальные страницы со сбоями вроде перекрытий, редиректов и медленной загрузки, проверяет ожидаемый результат, сохранность вкладки и ограничение времени ([README: Gauntlet](https://github.com/anomalyco/browser-control/blob/main/README.md#development)). Для better-axi подобные сценарии можно использовать для проверки диагностики блокировок, `STALE_REF`, восстановления после ошибки действия и того, что агент не потерял исходную страницу.

3. **Сокращать контекст PAG с помощью snapshot-дельт.** Browser Control умеет возвращать полный базовый snapshot, затем `unchanged` или компактные дельты, оставляя refs действительными при совместимом состоянии страницы ([README: snapshots](https://github.com/anomalyco/browser-control/blob/main/README.md#inspect-before-acting)). В better-axi каждый шаг уже получает полный AXI snapshot и строит из него доступные действия; полезный эксперимент — отправлять PAG только существенные изменения плюс полный актуальный набор целей. UID AXI и refs Browser Control различаются, поэтому копировать их протокол напрямую нельзя. Отдельная заметка уже описывает локальную реализацию дельты без зависимости от upstream: [`research-snapshot-delta.md`](research-snapshot-delta.md).

4. **Сделать ручную передачу управления продолжимой.** `handoff()` ждёт ручной шаг и затем позволяет скрипту продолжить после проверки состояния страницы ([README: handoff](https://github.com/anomalyco/browser-control/blob/main/README.md#pause-for-human-only-steps)). Сейчас `better-axi` может вернуть статус `handoff`; продолжение того же цикла после CAPTCHA/2FA пригодится только если появится конкретный workflow, которому нужно ожидать человека, а затем автоматически возобновляться.

5. **Записывать ручной сценарий как черновик workflow.** Browser Control может превратить показанные пользователем действия в редактируемый код; значения паролей маскируются, а сгенерированный сценарий нужно дополнить проверками результата ([README: demonstrate](https://github.com/anomalyco/browser-control/blob/main/README.md#pause-for-human-only-steps)). Это потенциально ускорит создание новых интеграций, но требует отдельной модели хранения, ревью и исполнения; сейчас приоритет низкий.

## Что не переносить напрямую

`read-only` в Browser Control блокирует ввод через часть CDP-команд, но не является песочницей: доверенный скрипт всё ещё способен менять страницу через `evaluate`. Расширение также получает широкие права на браузер и существующие авторизованные вкладки ([README: safety](https://github.com/anomalyco/browser-control/blob/main/README.md#safety-boundaries)). Поэтому этот режим нельзя трактовать как сильную границу безопасности или бездумно добавлять выполнение произвольного Playwright-кода в better-axi.

## Рекомендация

В ближайшей работе усилить проверку постусловий в `nav` и покрыть цикл небольшим набором локальных adversarial-сценариев. Затем измерить, насколько дельты snapshot сокращают payload PAG без ухудшения выбора целей. Handoff-продолжение и запись сценариев рассматривать после появления конкретного пользовательского workflow.
